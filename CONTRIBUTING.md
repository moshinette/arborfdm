# Contributing to ArborFDM

Thanks for helping. Issues and pull requests are welcome in **English or French** (les issues et PR en français sont les bienvenues).

The most useful contributions right now are **real print results**: which profile, printer, nozzle and slicer, and photos of what held, what broke and how easily the supports came off. Nothing in the profiles has been validated by many printers yet.

## Development setup

Python 3.10.1 to 3.14, 64-bit (3.12 recommended). Python 3.15+ is not supported yet because `manifold3d` has no wheel for it; Python 3.10.0 crashes PyInstaller.

```
git clone <repository URL> arborfdm
cd arborfdm
python -m venv .venv
# Windows: .venv\Scripts\activate      Linux/macOS: source .venv/bin/activate
python -m pip install -e ".[gui,dev]"
```

Linux needs the usual Qt/OpenGL system libraries (Debian/Ubuntu: `libegl1 libgl1 libxkbcommon0 libxkbcommon-x11-0 libdbus-1-3 libfontconfig1`).

Run the app with `python -m arbor.app.main` (or `scripts/run_dev.sh`, `scripts\run_dev.bat`) and the CLI with `python -m arbor --help`.

## Tests

```
QT_QPA_PLATFORM=offscreen python -m pytest -q          # Linux / macOS
set QT_QPA_PLATFORM=offscreen && python -m pytest -q   # Windows cmd
python -m pytest -q -m "not slow"                      # quicker subset
```

The full suite takes about 6 minutes on 2 cores. CI (`.github/workflows/tests.yml`) runs it on Linux and Windows for every pull request.

- Engine changes need a test, ideally on a synthetic model from `tests/models/synthetic.py` (add one if needed). Tests must not depend on files you cannot publish.
- Do not mark a test as passing that you did not run; say what you ran in the PR.

## Code layout and style

- `arbor/engine/` and `arbor/core/` never import Qt: the engine must stay usable from the CLI and tests. GUI code lives in `arbor/app/`.
- Units are millimetres, Z up, build plate at z = 0.
- Python 3.10 syntax (`from __future__ import annotations`, type hints), PEP 8, lines up to about 100 characters. Keep functions small and name things after the geometry they handle.
- No new runtime dependency without discussing it in an issue first (it ends up in the Windows build and in `docs/LICENSES.md`). Only licenses compatible with the GPL v3 (permissive, LGPL dynamically linked, GPL v3).
- Keep docs in sync: `docs/` for behaviour, `CHANGELOG.md` under "Unreleased" for anything user-visible.

## Proposing or changing a profile

Profiles are JSON files in `profiles/` (`_nozzle_02.json` / `_nozzle_04.json` hold the shared values, the others inherit and change density). A profile change must come with:

1. printer, nozzle, layer height, filament, slicer and version;
2. the model used: the printable test bench (`python scripts/make_tip_bench.py --supports`, protocol in `docs/PHYSICAL_TESTS.md`) or another model you are allowed to share;
3. photos of the print with supports and after removal, and what you changed and why.

Custom parameter sets for your own printer can also be saved as user presets in the app without changing the built-in profiles.

## Models and assets: what you must not commit

- **No paid, Patreon, Kickstarter or otherwise licensed miniatures**, even small ones, even "just for a test", and no screenshots of them in docs or issues. Most miniature licenses forbid redistribution.
- Models in `examples/` and `tests/` are generated by `scripts/make_examples.py` and `tests/models/synthetic.py`. Prefer adding a generator over adding an STL file.
- Images and icons: only your own work or clearly licensed (CC0, CC-BY with credit in the PR).
- Do not use the name, logo or screenshots of other support tools or slicers beyond neutral factual mentions.

## Pull requests

- One topic per PR, a short description of what and why, and how you tested it (the template asks for it).
- By submitting a contribution you agree that it is published under the project license, GPL-3.0-or-later (`LICENSE`).
- Be kind and patient; see `CODE_OF_CONDUCT.md`.
